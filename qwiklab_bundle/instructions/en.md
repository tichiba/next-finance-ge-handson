# ネクストファイナンス：Gemini Enterprise ハンズオン（情報収集・社内調査・4部門データ分析＆多彩なチャート可視化）

本ドキュメントは、`explore.qwiklabs.com`（Labs for Sales）や Argolis 検証環境上で1つのラボ環境（GCPプロジェクト1個＋ユーザーアカウント11個：`user00`［講師・管理者用］＋ `user01`〜`user10`［受講者9名＋予備1名］）を払い出し、Gemini Notebook・Gemini Enterprise（GWS/社内文書横断検索 / モデル：`gemini-3.8-flash`）・**4種の部門別データ分析エージェント（BigQuery Conversational Analytics A2A連携：財務与信・コールセンターVOC・人事タレント・営業マーケROI）**を一気通貫で体験するための手順書です。

* **第1部**：ファシリテーター（講師）向け ラボ作成・事前セットアップ・クリーンアップ手順（Cloud Shell ワンライナー方式 / 11アカウント構成）
* **第2部**：受講者（9名＋予備1名）向け ハンズオン手順書（基本45分 ＋ 応用チャートショーケース）

## 第1部：ファシリテーター向け ラボ作成・事前セットアップ・削除手順

### 1. 初回のみ：explore.qwiklabs.com でのラボ枠（11ユーザー環境）の作成

`explore.qwiklabs.com` 上で「GCPプロジェクト1個＋ユーザー11個（`user00`：管理者用1 ＋ `user01`〜`user10`：受講者用10）」を払い出すラボ枠を作成します（Startup Script の複雑な審査・デバッグを不要にし、ラボ起動後に Cloud Shell からワンライナーで全環境を自動構築する方式です。Argolis 環境で事前検証する場合はそのまま「2. 自動構築手順」へ進んでください）。

1. シークレットウィンドウで `https://explore.qwiklabs.com` に `@google.com` アカウントでログインします。
   * 右上のアイコンからロールが **Creator** であることを確認します（Student の場合は `http://go/preregister` から Creator 権限を申請します）。
2. 左上のメニュー（`☰`）から **Authoring** → **Labs** を開き、右上の **[+ Create new lab]** → **GCP** を選択します。
3. 以下の基本項目を入力して **[Create Lab]** をクリックします。

| 設定項目 | 設定値 | 備考 |
| :--- | :--- | :--- |
| **Title** | ネクストファイナンス：Gemini Enterprise ハンズオン | 任意の識別しやすいタイトル |
| **Duration** | `180` | 事前準備（12:00開始）＋ハンズオン本番（45分）＋バッファ |
| **Max Duration** | `240` | 最大延長時間（4時間） |
| **Level** | `Intermediate` | 中級 |
| **Fleet / Variant** | `gcpd` | 標準 GCP プロジェクト |
| **Number of Users** | `11` | `User 1`（`user00`: 講師/管理者用）＋ `User 2`〜`User 11`（`user01`〜`user10`: 受講者9名＋予備1名） |

4. 作成したラボの **Instructions** タブを開き、受講者向けハンズオン手順書（45分コア版 Google ドキュメント）を `qwiklabs-publisher@google.com` に閲覧共有した上で、ドキュメントの URL を貼り付けて **[Submit]** をクリックします。
5. **Environment Outputs** タブを開き、`Open Google Cloud Console`、`GCP Project ID`、および `User 1`（`user00`：講師・管理者用）〜 `User 11`（`user01`〜`user10`：受講者・予備用）のメールアドレス（Username）・共通パスワード（Password）・Google Drive リンクが表示されるよう設定して **[Update Environment Outputs]** を保存します。

### 2. 当日12:00（ハンズオン開始前）または Argolis 検証時：Cloud Shell 3分自動構築

当日の会場入り・PC事前セットアップ時（12:00〜）または Argolis 環境での事前テスト時に、ファシリテーターがラボを1回起動し、`user00`（Qwiklabs `User 1`）で Cloud Shell からワンライナーを実行して環境一式を構築し、貸出 Chromebook 9台（＋予備1台）へ `user01`〜`user10`（Qwiklabs `User 2`〜`User 11`）で事前ログインします。

#### Step 1：Cloud Shell の起動と ZIP アップロード（1分）

1. Google Cloud コンソール右上の **Cloud Shell（`>_` アイコン）** を起動します（Qwiklabs の場合は管理者アカウント `user00` ＝ `User 1` でログインします）。
2. 手元の PC にある **`next-finance-ge-handson-qwiklab.zip`** を、Cloud Shell のターミナル画面上へ**ドラッグ＆ドロップ**してアップロードします（または Cloud Shell 右上の「︙」メニュー →「アップロード」から選択します）。

#### Step 2：自動構築ワンライナーの実行（約3分）

Cloud Shell で以下のコマンドをコピー＆ペーストして実行します。

```bash
unzip -q -o next-finance-ge-handson-qwiklab.zip -d handson && bash handson/tf/scripts/setup.sh
```

このコマンド1つで、以下の環境構築がすべて全自動で完了します。

| 自動構築される対象 | 構築内容の詳細 |
| :--- | :--- |
| **1. API 有効化・ライセンス構成** | `discoveryengine`、`geminidataanalytics`、`bigquery` 等のAPI有効化、および全ユーザーの Gemini Enterprise ライセンス自動割当設定 |
| **2. Cloud Storage 資料配置** | `gs://<PROJECT_ID>-next-finance-handson` を作成し、シナリオ1用 IR PDF（2点）、シナリオ2用 社内規程・メール・Chat履歴 PDF（2点）、および全4データセットのCSV・スキーマ一式をアップロード |
| **3. BigQuery 4データセット（計12テーブル）作成** | ① `next_finance_handson`（請求・入金・与信）<br>② `next_finance_callcenter`（コールセンター入電ログ・オペレーター・CSATアンケート）<br>③ `next_finance_hr`（社員マスタ・月次勤怠・エンゲージメントサーベイ）<br>④ `next_finance_sales_mktg`（マーケティング施策・見込み客リード・商談パイプライン） |
| **4. 社内文書データストア＆GWS連携** | 社内文書データストア（`next-finance-internal-docs`）を作成してGCSからシナリオ2用PDFを自動インポートし、Google Drive / Gmail コネクタを登録 |
| **5. Gemini Enterprise エンジン** | アプリ `ネクストファイナンス Gemini Enterprise ハンズオン`（`next-finance-ge-app`）を作成し、既定モデルに **`gemini-3.8-flash`** を設定してデータストアを紐付け |
| **6. 4種の A2A データ分析エージェント** | BigQuery Conversational Analytics 上に4つの部門別データエージェント（財務与信 / コールセンターVOC / 人事タレント / 営業マーケROI）を作成・公開し、Gemini Enterprise へ一括登録 |

#### Step 3：Gemini Enterprise Web アプリ URL と資料ダウンロード URL の取得（1分）

1. スクリプト完了時に Cloud Shell に表示される **Gemini Enterprise 管理画面 URL**（またはコンソールの **AI Applications → Apps → ネクストファイナンス Gemini Enterprise ハンズオン**）を開きます。
2. 左メニューの **Integration（統合）** をクリックします。
   * **Identity Provider（ID プロバイダ）** が未設定の場合は、**Google Identity** を選択して **[Save]** をクリックします。
3. 画面中段に表示される **Web App URL（`https://vertexaisearch.cloud.google.com/home/cid/...`）** をコピーします。
4. 受講者用10アカウント（`user01`〜`user10` ＝ Qwiklabs `User 2`〜`User 11`：受講者9名＋予備1名）について、貸出 Chromebook 上で以下をセットアップ・案内します：
   * 各自のログインID（`user01`〜`user10` ＝ `User 2`〜`User 11`）と共通パスワード
   * コピーした **Gemini Enterprise Web App URL**（または短縮URL `goo.gle/ntt-gemini`）
   * **ハンズオン用 Codelab ページ**（プロンプト1クリックコピー ＆ 統合報告書・IR資料ダウンロードリンク掲載）
   * Cloud Shell の完了サマリーに表示された **シナリオ1用 IR 資料 PDF（2点）のダウンロード URL**

### 3. 検証・ハンズオン終了後：全リソースの一括削除（クリーンアップ手順）

Argolis 等で検証した後に作成したリソース（カスタム A2A エージェント4種、OAuth 認可設定、BigQuery データエージェント4種、Gemini Enterprise エンジン、データストア、BigQuery データセット4種、GCS バケット）をすべて削除する場合は、Cloud Shell で以下のコマンドを実行してください。

```bash
bash handson/tf/scripts/cleanup.sh
```

### 5. シナリオ3（18分）：【財務・審査エージェント】「請求・入金・与信」3DB突合分析と経営会議レポート作成

1. Gemini Enterprise 左メニューの **エージェント（Agents）** から **『請求・入金・与信分析』** を選択します（初回のみ承認ボタンをクリックします）。
2. 以下のプロンプトを順に入力します。

#### Step 3-1：月次回収率推移の折れ線グラフとリスク集中セグメントの特定

```bash
2026年4月〜9月の月次請求総額・入金済額・未収残高・回収率の推移を集計し、折れ線グラフで可視化してください。あわせて、契約区分および業種/セグメント別・与信ランク別に6ヶ月累計の「請求総額」「現在の未収残高と未収率」を集計し、どのセグメントにリスクが集中しているか教えてください。
```

#### Step 3-2：要注意法人トップ10社の棒グラフ比較と債権保全シミュレーション

```bash
法人_多回線一括請求の要注意顧客（ランクC1・C2）について、累積未収残高が多いトップ10社を抽出して棒グラフで比較してください。
さらに社内規程（第14条・第18条）に基づき、各社の与信限度額を20%圧縮した場合の新与信枠と、未収残高の60%を債権保証で保全カバーした場合のリスク低減額および残余リスク額を試算してください。
```

#### Step 3-3：経営会議向け対策レポートの作成と Google ドキュメント出力

左メニューの **ホーム（Home）** に戻り、以下のプロンプトでレポートを作成して **[Google ドキュメントにエクスポート]** をクリックします。

```bash
これまでの調査結果（東都ロジスティクス社からの支払期日延長相談の経緯・社内規程第11条/14条/18条のルール、およびBigQuery 3DB突合分析による2026年4月〜9月の回収率推移98.8%→93.8%・要注意法人トップ10社・債権保全シミュレーション結果）を統合し、来週の経営会議に付議するための『大口契約先の支払条件変更に関する決裁伺いおよび全社ビリング債権リスク対策レポート』を作成してください。
```

#### Step 3-4：コピペ不要！メインチャットから `@請求・入金・与信分析` を呼び出し、そのまま Canvas で経営会議用スライドを自動生成

左メニューからエージェント個別画面を開かなくても、**ホーム（メインチャット）の入力欄で `@` を入力してエージェントを直接呼び出し、同じチャットスレッドのまま Canvas でプレゼンスライドを自動生成**できます（コピペ不要で直前の分析結果が引き継がれます）。

1. **ホーム（メインチャット）** の入力欄で `@` を入力し、候補から **`@請求・入金・与信分析`** を選択して以下を実行します。

```bash
@請求・入金・与信分析 2026年4月〜9月の月次回収率の推移と、要注意法人（ランクC1・C2）の未収残高トップ5社、および与信枠20%圧縮・債権保証60%適用時のリスク低減効果を集計して要約してください。
```

2. 分析結果が表示されたら、**画面を切り替えずにそのまま同じチャット入力欄で** **[ツール（Tools）] → [Canvas]** を選択し、以下を入力して送信します。

```bash
今の分析結果をもとに、来週の経営会議で発表するための報告用プレゼンスライド（全5枚：1.エグゼクティブサマリ、2.月次回収率の推移と課題、3.要注意法人トップ5社の未収状況、4.与信枠圧縮・債権保証によるリスク低減シミュレーション、5.今後のアクションプラン）を作成してください。
```

3. 画面右側の **Canvas ペイン** に5枚構成のスライドが自動生成されます。右上の **[エクスポート（Export）] → [Google スライドにエクスポート]** をクリックすると、そのまま Google スライドとして保存・編集できます。

### 6. シナリオ4（応用ショーケース①）：【コールセンター・VOC分析エージェント】で多彩なチャートを体験

左メニューの **エージェント（Agents）** から **『コールセンター分析』** を選択し、以下のプロンプトで **散布図・円グラフ/ツリーマップ・積み上げ棒グラフ/ヒートマップ** を描画します。

#### ① 散布図（Scatter Chart）：オペレーター別 AHT × 一次解決率（FCR）× CSAT の相関分析

```bash
オペレーター別の「平均処理時間（avg_handle_time_sec）」と「一次解決率（first_call_resolution_rate）」の相関関係を散布図（Scatter Chart）で描画してください。あわせて、処理時間は短い（早切りしている）のに一次解決率や顧客満足度（avg_csat_score）が著しく低い要注意オペレーターを特定してください。
```

#### ② 円グラフ / ツリーマップ（Pie Chart / Treemap）：問い合わせカテゴリ＆詳細理由の構成比

```bash
入電ログ（call_logs）から、問い合わせ大分類（inquiry_category）ごとの入電件数シェアを円グラフ（Pie Chart）で可視化してください。さらに、大分類×詳細理由（inquiry_sub_reason）の2階層のボリューム構成比をツリーマップ（Treemap）または内訳グラフで表示してください。
```

#### ③ 積み上げ棒グラフ / ヒートマップ：曜日 × 時間帯別の入電集中と放棄呼（あふれ呼）の特定

```bash
曜日（day_of_week）および時間帯（hour_slot）ごとの入電件数と放棄呼（is_abandoned=1）の発生状況を、時間帯別の積み上げ棒グラフ（またはヒートマップ）で可視化し、どの曜日・時間帯にオペレーター増員が必要か提案してください。
```

### 7. シナリオ5（応用ショーケース②）：【人事・働き方＆タレント分析エージェント】で多彩なチャートを体験

左メニューの **エージェント（Agents）** から **『人事・タレント分析』** を選択し、業種を問わずあらゆる企業のコーポレート部門で活用できるピープルアナリティクスを体験します。

#### ① 散布図（Scatter Chart）：月平均残業時間 × エンゲージメントスコアの負の相関

```bash
社員マスタ（employees）のデータから、「直近6ヶ月平均残業時間（avg_overtime_hours_6m）」と「エンゲージメント総合スコア（engagement_score）」の関係を散布図（Scatter Chart）でプロットしてください。残業が何時間を超えるとエンゲージメントが急落し離職リスク（High_要ケア）が急増しているか、本部別の傾向とあわせて分析してください。
```

#### ② 複合チャート（Combo Chart：棒＋折れ線）：月次の採用・退職人数と平均残業時間の推移比較

```bash
月次勤怠データ（attendance_monthly）を集計し、2026年4月〜9月の月別の「退職発生人数（is_retiredの合計：棒グラフ）」と「全社平均残業時間（overtime_hoursの平均：折れ線グラフ）」を1つの複合チャート（Combo Chart）で描画して、残業増加と退職増加の連動性を教えてください。
```

#### ③ ツリーマップ（Treemap）：本部 × 職種別の人員数・人件費ボリューム構成比

```bash
本部（division_name）× 職種（job_role）ごとの在籍人数と人件費総額（annual_salary_jpyの合計）を集計し、ツリーマップ（Treemap）で組織の人員・コスト構造を可視化してください。
```

### 8. シナリオ6（応用ショーケース③）：【営業パイプライン・マーケROI分析エージェント】で多彩なチャートを体験

左メニューの **エージェント（Agents）** から **『営業・マーケROI分析』** を選択し、マーケティング投資対効果と営業パイプラインの可視化を体験します。

#### ① 散布図（Scatter Chart）：キャンペーン投下費用 × 創出商談パイプライン金額（ROI）の相関

```bash
マーケティング施策（marketing_campaigns）について、X軸に「投下費用（spend_jpy）」、Y軸に「創出商談金額（pipeline_generated_jpy）」をとった散布図（Scatter Chart）を描画してください。高コストなのにROIが低い施策と、低コストで高い商談金額・受注率（win_rate_pct）を生んでいる高効率チャネルを特定してください。
```

#### ② 円グラフ / ドーナツチャート（Pie Chart）：商談フェーズ別のパイプライン金額シェア

```bash
商談パイプライン（sales_opportunities）について、現在の商談フェーズ（stage_name：5段階）ごとの商談金額（deal_amount_jpy）の構成比を円グラフ（Pie Chart）で描画し、フェーズ別の件数・期待金額（weighted_amount_jpy）とあわせて要約してください。
```

#### ③ 積み上げ面グラフ（Stacked Area Chart）：チャネル種別ごとの月次創出商談額の推移

```bash
2026年4月〜9月の商談発生月（created_month）ごとに、獲得チャネル種別（channel_category）別の商談金額（deal_amount_jpy）の推移を積み上げ面グラフ（Stacked Area Chart）で描画し、直近で急成長しているチャネルを教えてください。
```

#### ④ コピペ不要！メインチャットで `@営業・マーケROI分析` を呼び出し、そのまま Canvas でスライド化

1. 左メニューの **ホーム（メインチャット）** を開き、入力欄で `@` を入力して **`@営業・マーケROI分析`** を選択し、以下を実行します。

```bash
@営業・マーケROI分析 チャネル別の費用対効果（ROI・受注率）と、高スコア（80点以上）なのに未架電で放置されているリードの機会損失額を分析して要約してください。
```

2. 分析結果が出たら、**そのまま同じチャット欄で** **[ツール（Tools）] → [Canvas]** を選択し、以下を送信します。

```bash
今の分析結果をもとに、来期のマーケティング予算再配分とインサイドセールス改善を提案する役員報告用スライド（全5枚）を作成してください。
```

3. 右側の Canvas に生成されたスライドを確認し、**[エクスポート] → [Google スライドにエクスポート]** で Google スライドへ出力します。
